# 배정고 수강설계 점검표

학생이 작성한 수강 신청안, 담임 확인, 학교 공식 수강신청 결과를 서로 분리해 보존하고 비교하는 웹서비스입니다. 기존 단일 HTML은 `legacy/index.html`에 보존했습니다.

## 화면 주소

- 학생 화면: `/`
- 선생님 화면: `/teacher.html`

선생님 화면은 주소로 직접 접근해도 선생님 로그인이 먼저 표시됩니다.

## 로컬 실행

1. `.env.example`을 복사해 `.env.local`을 만들고 `ADMIN_PASSWORD`, `SESSION_SECRET`을 실제 값으로 변경합니다.
2. `npm install`
3. `npx wrangler d1 migrations apply DB --local --config wrangler.jsonc`
4. `npm run dev`

로컬 개발 중 환경변수가 없을 때만 선생님 비밀번호 `00000`을 사용할 수 있습니다. 배포 환경에서는 이 임시 비밀번호가 허용되지 않습니다.

## 주요 데이터 원칙

- 학생 신청안과 공식 최종 결과는 별도 테이블에 저장합니다.
- 공식 결과는 입학년도, 차수, 현재 반, 대상 학년·학기별로 저장합니다.
- 재업로드는 자동 덮어쓰지 않으며 해당 파일 범위만 교체합니다. 이전 자료와 작업 이력은 남깁니다.
- 학생 고유번호가 있으면 우선 사용하고, 없으면 입학년도·현재 반·현재 번호·이름으로 비교합니다.
- 과목 비교는 열 순서와 관계없이 과목 집합으로 수행합니다.

## 엑셀 업로드

선생님 페이지의 `실제 결과 업로드`에서 입학년도와 차수를 고른 뒤 여러 파일을 분석합니다. 미리보기에서 학생 수, 과목 수, 신규/교체/오류 여부를 확인하고 최종 반영합니다. `○`, `◯`, `O`, `o`를 신청 표시로 읽고 학생 정보가 없는 집계 행은 제외합니다.

## 아직 학교 자료가 필요한 부분

대학별 핵심·권장과목은 저장 구조와 추천 표시 로직을 준비했지만 실제 2028학년도 원본 자료가 저장소에 없으므로 데이터 입력이 필요합니다. 학교 교육과정은 선생님 페이지의 `기준자료 관리`에서 입학년도별로 직접 등록할 수 있습니다.
